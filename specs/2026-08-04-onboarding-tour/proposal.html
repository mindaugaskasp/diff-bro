Seven things a new DiffBro user never finds on their own

Four steps on first launch, three on the next. It points at the real controls, runs on shipped demo files, and can be switched off — or summoned back — at any point. Every view below is built from the app's own components and tokens; pick a theme and a step to see the actual surface.

How the overlay works

What it is made of

The veil is two layers, not one

Tint is a single element with a rounded hole clipped out (clip-path: path(evenodd, …)) — one layer, so the scrim can never overlap itself. Blur is four rectangles around the target, because Chromium resolves backdrop-filter before clip-path, so a clipped blur layer blurs straight through its own hole. Either job done the other's way produces a visible defect.

The hole stays live

Nothing covers the target, so it stays clickable and sharp — verified by capturing the spotlit region with the overlay on and off and comparing: identical to within 0.5%, against 25% when the blur leaks in.

The ring carries the meaning

A 2px --accent keyline. Never an accent glow — on matrix, nyan and neon a tinted shadow blooms into a halo. Worst case 3.21 : 1 (solar), clearing the 3 : 1 non-text floor on all 14.

The ring hugs, it does not hover

Drawn inside the target's own box, at zero offset. An outward offset collides with whatever the target sits flush against, and adjacent chrome is often already accent-coloured — the active tab's underline is the same 2px --accent, so a 5px offset over the file-slots band read as one thick edge instead of two elements.

Two cases the ring has to special-case

On an accent-filled target the ring flips to --text-on-accent, because accent-on-accent is invisible. And the hole's corners follow the target's radius — a square hole around a rounded control leaves un-veiled slivers that are harmless on a dark ground and read as a white halo on a light one.

A zone is dashed, not solid

The snippet-drag step targets the whole comparison pane, because useWindowFileDrop is bound to the root element and a drop lands anywhere. A dashed ring says "area", a solid one says "control" — and the callout moves inside the zone, since there is no "beside" for something that fills its pane.

Blur, because dimming is not enough

The veil blurs and desaturates as well. On the seven dark themes a black scrim changes almost nothing — beacon measures 1.00 — so defocus, not darkness, pushes the rest of the app back there.

Anchored by measurement

A step names a CSS selector; the overlay reads that element's box at run time. Nothing is placed by hardcoded coordinates, so the tour survives a collapsed sidebar, a resized window and a reordered section.

The finding that changed the design

The obvious build — a --bg-raised card with a --border keyline over a dimmed app — fails on 11 of 14 themes. Against a scrimmed ground that border drops to 1.23 : 1 on light, and the card stops lifting at all on the dark themes (matrix 1.06). The fix is that the two cues swap roles by ground: on light themes the callout's own face separates it (up to 3.23 : 1), on dark themes the --btn-edge keyline does (up to 18.4 : 1). Every theme gets one strong cue from the pair — the table below proves which.

User stories

Four steps, then three — not seven in a row

Someone who came to look at one file gets the survival set and is left alone. The depth waits for the next launch, by which point they have chosen to come back. Numbered because it is a real sequence: step 1 opens the demo files, step 2 seals them, and in run two step 5 saves a snippet that step 6 then compares.

Run one · first launch

The survival set. Four steps, ending on the switch that turns the rest off.

01

Load two files

As someone opening DiffBro for the first time, I want to know I can just drop two files on the window, so that I don't hunt for an import menu that doesn't exist.

  • Ships with demo-config-v1.json and demo-config-v2.json, written into the data directory on first run and opened as real files — so the step teaches the real path, not a simulation.
  • They open in a new tab, so a restored session is never displaced. Closing the tab is the only cleanup.
  • The ring sits on the file-slots band; copy names both routes — drop anywhere, or click a slot to browse.
  • Copy names the payoff: DiffBro picks the viewer — text, JSON tree, spreadsheet grid or diagram.
.file-slots-rowCtrl+1 / Ctrl+2tabsStore.newTab()demo fixtures
02

Seal it for a colleague

As someone who has just found a difference worth escalating, I want to hand it to a named colleague, so that I stop pasting screenshots into chat.

  • Share is pressed on the demo diff, so the step shows what a first-time user genuinely gets: the one-time setup dialog, because there are no trusted keys yet.
  • The ring lands on Add their key… — the actual blocker, named rather than glossed over.
  • Expiry is stated as the user-visible fact: it stops opening on a clock you set, and one week is the ceiling.
  • Nothing is sealed and no key material is generated. A throwaway demo identity would outlive the tour.
share-currentShareDiffDialogread-only step
03

Reach it all without switching windows

As someone deep in another app, I want to pull up a snippet or a tool with one chord, so that I don't alt-tab, hunt a window and lose my place.

  • Shows the real launcher summoned over the app: snippets and the 10 tools in one search, preview on the right, Enter to open and Ctrl+C to copy.
  • The callout names the payoff a new user would never guess — it works with DiffBro minimised, so it is a system-wide launcher, not a window feature.
  • Names the chord and where to rebind it, which is the Shortcuts pane the next step opens.
  • Previews the two examples first run already seeds, so the launcher has real results on day one — no empty-state lesson.
  • Constraint worth knowing before build: the launcher is a separate BrowserWindow (src/main/quickLook.js), so the main window's overlay cannot ring a control inside it. This step rings the whole panel and stops there — anything finer means shipping the tour into the launcher's renderer too, which I'd rather not do for one step.

04

Make it yours — and turn this off

As someone who has now seen enough, I want to find the settings and stop the tips, so that the app gets out of my way.

  • Opens the real Settings dialog on Appearance. The theme grid is the most under-discovered thing in the app.
  • The last ring lands on the new Show tips after an update row, with Show tour beside it — run one's final act is showing both the off switch and the way back.
  • Names what else lives there: size limits, where your data is kept, the Quick look-up shortcut.
  • Finishing run one asks "Three more tips?" there and then. Skipping it instead turns tips off entirely — a skip is an answer, not a pause.

Run two · offered the moment run one ends

The depth. Three steps, offered by a plain "Three more tips?" dialog as soon as run one finishes — not deferred to a future launch, because this app stays open for weeks and that launch might be a month away. Only offered if run one was finished rather than skipped.

05

Keep something worth keeping

As someone who retypes the same staging payload every week, I want to park a piece of JSON where I can find it again, so that next week it is two keystrokes away.

  • The live step: the real editor, prefilled from the shipped demo payload, named and tagged.
  • The ring moves to Save. The user presses it and the snippet is genuinely theirs afterwards — which is the whole point of the step.
  • Closing instead also advances. A tour that cannot be refused is a modal wearing a costume.
  • It joins the two examples first run already seeds, so the library is never empty behind the tour.

06

Compare the snippets themselves

As someone with two versions of a config in my library, I want to diff them against each other, so that I don't have to write them out to files first.

  • The destination is the whole comparison pane, not the file box. useWindowFileDrop is bound to the root element, so a drop lands anywhere — teaching the narrow target would teach the wrong thing.
  • Dashed on both ends, because both are areas rather than controls, joined by the drag path with the snippet riding it as a ghost.
  • Copy states the full rule: a snippet can face a file, or another snippet.
  • Advancing never requires the drag. A mandatory drag is the one gesture a trackpad user can fail at.
useSnippetDraguseWindowFileDropanimated arrow
07

See a diagram change as a diagram

As someone reviewing an architecture change, I want to see which nodes moved, so that I am not reading Mermaid source line by line.

  • Covers both halves: a Mermaid snippet previews live in the editor, and two versions compared mark the changes on the picture.
  • The ring sits on the change register — the panel that turns a picture back into a reviewable list.
  • Marks are encoded twice, colour and stroke or badge, so the read survives greyscale and colour-blindness.
  • Waits on useDiagramWarmup rather than showing an empty frame while Mermaid loads.

Opting out, and back in

Four ways out, three ways back

The tour can be left at any point, from any step, and leaving is never punished by having to sit through it again. It can also be summoned at any point, from three places, whether it was finished, skipped or switched off years ago.

Escape

Closes the tour from any step — the same key that closes every dialog in the app.

Skip tour

A .btn-ghost in every callout footer, legitimately the dismissive twin of the Next primary beside it. Present on step 1, not held back for the end.

The toast that follows

Leaving early shows one line: "Tips off. Turn them back on in Settings ▸ Appearance." An opt-out the user cannot reverse is a trap.

Settings ▸ Appearance

Show tips after an update — off means off for good, including future versions. It is the row run one ends on, so it is found on day one rather than stumbled on later.

Three ways back in, always available

Help ▸ Show tour

In the menu bar for good, next to Keyboard Shortcuts. Replays all seven steps from the start, ignoring every flag — including showTips = false. Asking for it is not the same as consenting to automatic tips, so it never silently switches them back on.

Settings ▸ Appearance ▸ Show tour

A button beside the tips toggle, so the place you turn it off is the place you turn it back on. Same behaviour: all seven, from step one.

Command palette

Show onboarding tour, reachable from the palette and therefore searchable — which is how anyone who half-remembers a feature actually looks for it.

Per-theme verdict

Measured, not eyeballed

Parsed from styles/themes.css with the resolver check-theme-depth.mjs uses — color-mix included, and the scrim composited over each ground. Floors are the repo's own: 4.5 text, 3.0 non-text, 1.11 border, 1.04 surface.

ThemeGroundTitleBody KeylineCard liftRing DimWhat carries the focus

Dim is how much the scrim actually changes the app behind it. Below about 1.25 it is not a visible cue — which is every dark theme, and beacon at 1.00 is a pure-black ground that cannot be darkened. That column is why the veil blurs. Keyline and Card lift are the complementary pair: read them together, never alone.

Shape of the change

What lands in the tree

New slice

features/onboarding/ — onboardingStore.js, index.js, components/TourOverlay.vue + TourCallout.vue and their styles/. Tests mirror to tests/renderer/features/onboarding/.

Pulled out to pure units

useSpotlight.js owns measuring and placement; utils/tourSteps.js the step list and the since-versus-seen filter. Both unit-testable without mounting anything — the lesson from the Mermaid resize bug.

Shipped demo files

Two JSON fixtures bundled with the app and written once into the data directory, so step 1 opens real files by real path and step 2 has something real to seal. They stay for the user to reopen.

Touched, not rewritten

Two persisted keys in settingsStore, one row in utils/commands.js, one Help item in both src/main/index.js and MenuBar.vue, one toggle in SettingsDialog.

Guards to extend

A tour-callout surface added to SURFACES in theme-sweep.mjs so the numbers above are re-proved against the live DOM, plus an e2e that runs the tour to the end and one that leaves it at step 1.

Docs that go stale

README.md (feature status), docs/roadmap.md, and the first-run screenshot set — empty-state.png now has a tour over it on a fresh profile.

Decided

Demo JSON files ship with the app. Written into the data directory on first run and opened by path, so the comparison and the seal-and-share step both run on something real. Falls back to an in-memory comparison if the write fails.

Decided

Quick look-up is a step. Placed sixth, after a snippet exists to find, so the search demonstrates itself on the user's own data. It rings the whole launcher panel — see the constraint under story 06.

Decided

Four, then three. Run one is comparing, sealing, quick look-up and settings; run two is keeping a snippet, diffing snippets and diagrams, offered on the next launch. Settings moves to the end of run one so the off switch and the replay button are found on day one rather than six steps deep.

Decided

Run two is offered immediately, by a dialog. A diff viewer stays open for weeks, so "next launch" is not a schedule — it could be a month away, landing run two on someone who has forgotten there was a tour. Run one now ends with a plain BaseDialog: Three more tips? · Not now · Show me. "Not now" asks once more on the next launch and then stops; it never nags in-session.

Decided

The tour is replayable for good. Help ▸ Show tour, a button in Settings, and a command-palette entry — all three replay all seven steps and ignore every flag, including a tips opt-out. Asking to see it once is not consent to automatic tips, so replaying never re-enables them.
